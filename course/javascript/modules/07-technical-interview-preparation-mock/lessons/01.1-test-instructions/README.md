# Test Instructions

Welcome to the **Technical Interview Preparation** mock test.

## What is assessed

This screening covers module **07 — Technical Interview Preparation**:

- System design trade-offs: Consistency, Availability, Partition tolerance (CAP theorem)
- Behavioral storytelling structured with the STAR method (Situation, Task, Action, Result)
- Asking clarifying questions that target constraints, ties, and concrete examples
- Code quality smells (leftover debug output, unresolved TODOs, `var` scoping)
- Iterative optimization narration: brute force → better → optimal

## Before you begin

- You have **90 minutes** for all sections.
- **Passing score:** 70%.
- Multiple-choice answers are scored automatically (1 point each; no negative marking).
- The coding challenge uses **stdin/stdout** — same I/O pattern as HackerRank ([STDIN/STDOUT](https://candidatesupport.hackerrank.com/articles/8758620864-using-stdin-for-inputs-and-stdout-for-outputs)).
- Use **Node.js only**; no external libraries.
- Do not refresh the page during the timed session (progress is stored locally).

## Practice mode vs real HackerRank

This simulator matches the **section order and skills** of common JS screenings but is friendlier than many production tests: one coding problem, visible test cases, and no section timer lock-in. See the module README for a full comparison.

## Section order

1. **Multiple choice** — 8 questions on CAP theorem, STAR structure, clarifying questions, code quality, and optimization narration
2. **Coding challenge** — implement a STAR line validator that checks four stdin lines represent filled STAR slots
