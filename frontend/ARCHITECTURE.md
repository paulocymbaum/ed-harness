# Frontend architecture

Technical reference for routes, layers, catalog shape, and scores. For navigation UX and student journey, see [`ARCHITECTURE-FRONT.md`](./ARCHITECTURE-FRONT.md). For on-disk content layout, see [`../COURSE_STRUCTURE.md`](../COURSE_STRUCTURE.md).

## Route hierarchy

| Route | Component | Purpose |
|-------|-----------|---------|
| `/` | `CatalogRoute` | Course list (default tab) |
| `/?tab=content-map` | `CatalogRoute` → `ContentMapPanel` | Curriculum mind map with scores and collapsible branches |
| `/course/:courseId` | `CourseExperienceRoute` | Branches: hierarchy overview or legacy tabs |
| `/course/:courseId/module/:moduleId` | `ModuleLayoutRoute` | Module shell: drawer + outlet (study) or redirect to mock test |
| `/course/:courseId/module/:moduleId` (index) | `ModuleExperienceRoute` | Module README |
| `/course/:courseId/module/:moduleId/lesson/:lessonId` | `LessonWorkspaceRoute` | Lesson explanation + activity drawer |
| `/course/:courseId/module/:moduleId/mock-test` | `MockTestExperienceRoute` → `MockTestOverviewRoute` | Mock test landing + section nav shell |
| `/course/:courseId/module/:moduleId/mock-test/section/:sectionId` | `MockTestSectionRoute` | Instructions, quiz, or coding section |

### Course overview (hierarchy)

`CourseOverviewRoute` renders two lists from the same course entity:

- `course.modules[]` — study modules (folder ids **not** ending in `-mock`)
- `course.mockTests[]` — timed assessments (folder ids ending in `-mock`)

### Lesson workspace drawer (URL state)

- `?drawer=quiz&quiz=<id>` — quiz session in drawer (`QuizHost` layout `drawer`)
- `?drawer=project&project=<id>` — project workspace in drawer (`ProjectReader` layout `drawer`)
- `?drawerTab=files|delivery` — project drawer tab

When a quiz or project drawer is open, the main explanation pane is hidden; the drawer occupies the main column on desktop.

### Module-level quiz

- `?quiz=<id>` on module route — full-page `QuizHost` layout `page`

### Mock test routing

- `ModuleLayoutRoute` redirects `/module/<id>-mock` → `…/mock-test`
- Child routes under `mock-test` render `Outlet` without the study module shell
- Section types map to shells:
  - `instructions` → `ReadmePanel`
  - `quiz` → `QuizHost` (`page`)
  - `coding` → `ProjectReader` (`drawer`, Delivery tab)

Navigation hooks: `useMockTestNavigation`, `useMockTestRouteData`. Selectors: `mockTestSelectors.ts`.

Mock tests simulate HackerRank screening **shape** (instructions → MCQ → stdin/stdout coding) in practice mode; alignment details and official HackerRank doc links: [`.cursor/skills/create-mock-test/reference.md`](../.cursor/skills/create-mock-test/reference.md#hackerrank-alignment).

### Legacy courses

Courses with `structure: "legacy"` use flat tabs and `ContentReaderDialog` overlay. Mounted in `AppLayout` only when `course.structure === "legacy"`. See `features/course-legacy/`.

## Catalog entity model

Generated by `scripts/generate-static-catalog.mjs` into `infrastructure/static/catalog.json`.

```text
Course (hierarchy)
  modules[]     ← study modules
  mockTests[]   ← modules whose id ends with -mock
  lessons[]     ← flatten (all modules + mock tests)
  projects[]
  quizzes[]
```

Types: `domain/types/catalog.ts`, `domain/types/mockTest.ts`.

| Type | Key fields |
|------|------------|
| `Module` | `lessons`, `projects`, `quizzes` |
| `MockTestModule` | same + `mockTest: MockTestMeta` |
| `Lesson` | `markdown`, `mockTestSection?` |
| `MockTestMeta` | `durationMinutes`, `passingScorePercent`, `sections[]` |

`getModuleById` returns study modules only. `getMockTestById` / `getModuleOrMockTestById` cover mock tests for breadcrumbs and layout.


## Score and deliverables

- Score file: `course/<courseSlug>/quiz/score.json` (one file per course)
- Progress keys (localStorage): `${courseId}:quiz:${lessonId|_}:${quizId}` and `${courseId}:project:${lessonId|_}:${projectId}`
- Score file storage keys use `${lessonId}/${id}` when scoped to a lesson
- Dev API plugins validate course slugs (`javascript`) and hierarchy `rootPath` values

## Manual checklist (hierarchy)

1. Open `/course/javascript` — **Modules** and **Mock tests** lists appear separately
2. Open a study module — side drawer shows sections, lessons, quiz/project links
3. Open a lesson — explanation visible in main pane
4. Click a project — drawer opens; main explanation hidden; lesson progress stays in drawer footer
5. Switch drawer tabs (Files, Delivery) — drawer content updates
6. Complete quiz in drawer — results shown; close returns to lesson explanation
7. Reload page — drawer state restored from URL; progress syncs from `score.json`
8. Module quiz (`?quiz=`) — full-page quiz; back returns to module README
9. Open a mock test card — `/mock-test` overview with section nav
10. Walk sections: instructions → quiz → coding; coding **Run answer** uses `tests.json`

## Manual checklist (legacy, if present in catalog)

1. Tabs README / Examples / Projects / Quiz work
2. `ContentReaderDialog` opens from Examples/Projects; Escape closes and restores tab
3. Project delivery panel works in overlay
